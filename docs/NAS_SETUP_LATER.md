# NAS 설정 — 다음에 함께 진행

**이번 개발에서는 NAS에 접속하거나 설정을 바꾸지 않았다.** 앱은 로컬 교환 폴더로 먼저 검증한다. 아래는 추후 공동 설정 체크리스트이며, 실제 DSM 화면·장비 사양·기존 공유 정책을 확인한 뒤 세부 명령을 정한다.

## 설정 전에 확인할 사항

- NAS 모델, DSM 버전, 여유 용량과 현재 백업 방법.
- 맥미니와 미니에서 같은 네트워크의 NAS에 접근 가능한지.
- 노트북이 외부에서도 접속해야 하는지. 외부 접속 방식은 별도로 결정한다.
- 기존 자료를 건드리지 않는 새 교환 폴더의 이름·계정·권한.
- 맥 로컬 SSD의 입력 복사·모델·결과 저장 공간.

## 함께 할 순서

1. 새 전용 교환 공유 폴더를 만든다. 기존 Study Manager 데이터나 원본 프로젝트 폴더와 합치지 않는다.
2. 준비 PC와 허브의 계정을 구분한다. 준비 PC는 자신의 outbox 작성과 receipts/results 읽기가 필요하다. 허브는 모든 outbox 읽기와 receipts/results 쓰기가 필요하다. 정확한 하위 폴더 ACL 구현은 실제 DSM에서 확인한다.
3. Windows 경로와 macOS 마운트 경로를 각각 확인한다. 경로 문자열은 달라도 같은 폴더를 가리키면 된다.
4. 양쪽 앱에서 교환 폴더를 지정한다. 허브 `--home`은 맥 로컬 디스크로 유지한다. SQLite·모델·가상환경은 NAS에 두지 않는다.
5. 소형 파일 1건을 전달한다. 복사 중 인수 거부, 복사 완료 후 성공을 확인한다.
6. 맥 인수 상태를 미니에서 확인하고 미니를 종료한다. 맥이 전사를 끝내고 결과를 NAS로 내보내는지 확인한다.
7. NAS 연결이 끊겨도 이미 인수한 작업의 로컬 결과가 남는지 확인한다. 재연결 후 export로 발행을 재시도한다. 현재 자동 재연결·재발행 기능은 없다.
8. 다른 PC의 고유 device_id로 제출해 서로 결과가 섞이지 않는지 확인한다.
9. 공유 폴더 백업과 맥 허브 로컬 폴더 백업을 별도로 정한다. 허브 종료 상태에서 DB·inputs·results를 함께 백업하고 복원 시험한다.

## 완료 판정

- 인수 전 미니 종료: 전송 미완료는 실행되지 않고 다시 전송할 수 있다.
- 인수 후 미니 종료: 맥이 자기 로컬 입력으로 끝까지 처리한다.
- 맥 종료: 새 작업이 대기하며 다른 PC에서 AI가 자동 실행되지 않는다.
- NAS 연결 끊김: 로컬 완료 결과가 유실되지 않으며 재연결 후 내보낼 수 있다.
- 모든 결과: complete.json의 해시가 실제 결과와 일치한다.

현재 앱은 수동 버튼 방식이다. NAS 설정만으로 자동 감시·부팅 시 자동 실행·공용 사전 병합이 생기지 않는다. 해당 기능은 별도 개발·검증 후 켠다.
