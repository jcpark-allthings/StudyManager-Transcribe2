# 단계별 개발 현황 — 0.1.0

기존 계획을 구현 여부와 장비 검증 여부로 구분합니다. 전체 단계를 완료한 것으로 처리하지 않습니다.

| 단계 | 이번 구현 | 남은 완료 조건 |
|---|---|---|
| 0. 독립 기반·계약 | 새 Python 패키지, 역할 분리, JSON 계약, 해시, 로컬 DB | 사용자 환경의 폴더·계정 경계 확인 |
| 1. 맥 단일 전사 | 큐·MLX 어댑터·TXT/JSON·재시도·중단 체크포인트 | 실제 맥에서 1개 MP3 전사, 품질·메모리 측정, 모델 선택 확정 |
| 2. 준비 앱 | 오디오 등록, TXT/MD/PDF 추출, 규칙 기반 후보, 편집, PC별 묶음 | Windows 실행 확인, PDF-XChange OCR 연계, 풍부한 결과 열람·자료 형식 |
| 3. 폴더 왕복 | 로컬 인수·상태·결과 발행, 원본 제거 후 실행 테스트 | NAS 실제 설정·권한·연결 끊김 시험, 자동 감시, 진행 중 취소 |
| 4. 여러 PC·공용 사전 | device_id 분리와 2개 PC 모의 제출 테스트 | 맥 전역 사전 저장소·버전·충돌 UI, 동일 콘텐츠 별도 요청 중복 정책, 10개 실전 순차 처리 |

| 7. 배포·운영 | 소스 실행 스크립트, CI 정의 | 실제 CI 확인, 서명 설치 파일, 자동 시작·업데이트·백업 복구 |

## 다음 구현 순서

1. 맥에서 5–10분 한국어 음성 1건으로 단계 1 검증. 실제 실패 메시지·모델 다운로드·처리 시간·최대 메모리 기록. 이 검증 전에는 실제 전사 성공을 주장하지 않는다.
2. 미니에서 준비 앱 실행 및 PDF 후보 검토. 후보는 빈도 기반이며 전문 용어를 정확히 선별하는 AI가 아니다.
3. 실제 두 PC 사이 수동 파일 전달과 인수 후 미니 종료 시험. NAS는 사용자가 준비될 때 별도 문서대로 함께 설정한다.
4. 자동 감시·오류별 상태 표시·결과 뷰어와 전역 사전 버전 관리를 추가한다. 충돌 시 자동 덮어쓰기하지 않는다.
5. AI 사전 정제와 교정은 맥 허브에만 추가한다. 외부 유료 호출은 제공자·키·비용 정책을 정한 후 시험한다.

## 범위를 제한한 이유

장비 접근 없이 실제 MLX 성능, Windows/macOS 설치, NAS 권한을 검증할 수 없다. 이 버전은 데이터 전달과 재실행 안전성을 먼저 확인하는 개발 미리보기다. 작업 취소는 QUEUED 상태만 가능하며, 전사 실행 중에는 다른 큐 변경도 잠금으로 거절한다. 장기 실행 관리와 중단 기능은 후속 구현으로 남긴다.
